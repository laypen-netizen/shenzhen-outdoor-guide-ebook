# 深圳户外景点指南内容与产品审查

审查日期：2026-07-19
范围：8 篇公众号本地 Markdown、330 个景点数据、69 张授权实景图、DOCX/PDF 附件、Web/H5 静态站与构建校验链。
结论：修复 3 个 Important 问题后，无未解决的 Critical / Important；保留 4 项后续优化，不阻断本地交付。

## 已修复问题

### Important：公众号全文存在被静态站误发布的风险

- 证据：用户指定的抓取目录位于 GitHub Pages 仓库内，包含 8 个 Markdown 和 428 个下载媒体文件；公众号公开可读不等于获得再发布许可。
- 修复：`.gitignore` 明确排除 `sources/`，并新增自动测试；`git check-ignore` 已确认正文和媒体均被忽略。
- 结果：正文仅供本地候选核对，文章图片没有进入 `assets/places/`、DOCX、PDF、Web 或 H5。

### Important：移动筛选控件低于 44px 触控门槛

- 证据：`.check-label` 与 `.mobile-filter-button` 的最小高度均为 42px，与产品规格不一致。
- 修复：先加入失败测试，再将两者提高到 44px。
- 结果：390px Chrome 实测筛选按钮、复选筛选区、菜单按钮、底部导航和详情操作均不低于 44px。

### Important：来源文档仍把 8 篇正文写成不可用

- 证据：OpenSpec、资料清单与电子书规格保留 `blocked_unavailable` 旧状态，与本轮已抓取事实冲突。
- 修复：来源审计升级为 `reviewed_local_markdown`，记录工具版本、路径、抓取时间、SHA-256、质量结果和候选景点；同步修正文档。
- 结果：8 个本地工件均通过哈希回读，且机器合同明确“仅作景点线索、图片不得用于发布、事实只认官方一手来源”。

## 本轮全站性能与工程审查（Darwin + Superpowers）

Darwin 的正式评分对象是 Skill 产品；本轮将其“先取基线、只保留可验证改善、验证结果形成棘轮”的约束用于网站。Superpowers 用于测试先行、真实浏览器验证和独立复核。

### 已修复

- **目录首屏过重**：卡片仅保留 60 字以内摘要，完整介绍继续保留在详情页；330 张景点图生成 720w / 960w 响应式版本并写入 `srcset`。
- **数据与资产校验缺口**：`srcset` 候选、缺失图片、真实存在数量、精选景点完整性均纳入校验；缺少任一精选景点或原图会使构建失败。
- **性能审查工具泄漏 Chrome 调试页**：每次检查均在 `finally` 中关闭 CDP 连接和临时 page target，并断言检查前后本机站点调试页数量不增加。
- **SEO / 分享回归缺口**：对每个公开页校验唯一的 canonical、meta description、`og:title`、`og:description`、`og:url`、`og:image`；本站 `og:image` 同时校验本地文件存在。

### 实测结果

在禁用缓存、390px × DPR 3 的本机 Chrome 基准中，目录首次传输由审查前约 1.44 MB 降至 956 KB；典型详情页由约 290 KB 降至 194 KB。桌面目录首次传输为 1.00 MB，典型详情页为 344 KB。六组桌面 / 移动页面检查均无横向溢出、坏图或控制台错误；移动首页高度为 4,787px，三组横向内容轨道可用，主视觉保持水平对齐。

### 保留为产品决策

- 目录仍保留 330 张静态卡片以保证无 JavaScript 时完整可浏览；若要进一步降低初始 HTML 和 DOM 体积，需要明确选择分页、按需加载或虚拟列表，并重新定义无 JS 可访问性与分享链接行为。
- 站点未加入离线 Service Worker / 大体积图片缓存。是否提供 PWA 离线包会改变存储占用与更新策略，需单独决策。

## 七种视角复核

- **Baoyu**：保留抓取原文，不借格式化之名改写或补造内容；8 篇均通过标题、正文长度、失败页关键词和媒体引用质量门。文章 8 标题称 30 条、正文仅见编号 1—29且含重复，按原状记录。
- **归藏**：延续图片第一公民、结构优于装饰、网格与留白原则。首页主视觉与信息层级清楚，逐景点实景和编辑配图有显式类型标签，不用公众号图片凑覆盖率。
- **花叔**：按理念、层级、工艺、功能、原创性五维检查。1440px 与 390px 均无横向溢出和坏图；唯一功能级问题是 42px 触控目标，已修复。
- **Superpowers**：沿用已批准的完整内容优化设计，不另起相互冲突的方案；实现遵循 330 景点、120—220 字介绍、完整出行字段、真实图许可和可验证交付合同。
- **OpenSpec**：公众号只作线索、官方来源作事实真源、编辑源与发布源分层、永久 ID 注册表和 validation-gated 迭代均已落实。
- **Darwin**：只采纳“改进必须通过验证并形成棘轮”的原则；新增来源审计、发布边界、触控目标和真实浏览器检查，不修改任何 Skill 产品。
- **数字生命卡兹克**：采用具体性、证据支撑、节奏和活人感检查，但不模仿人格、不虚构亲历、不加固定署名或粗口。景点文案保持可执行工具书语气。

## 保留的 Optimize 项

1. 330 个景点中仍有 261 张明确披露的编辑配图；继续扩充时只接受精确地点和开放许可双证据，不以相似图片换比例。
2. 抓取页未可靠提供作者和发布时间，审计字段保持空值；除非后续有可复核页面元数据，不做推断。
3. 8 篇文章合计记录 195 次候选提及、145 个唯一名称；别名、商业设施、泛称和旧路线尚需官方来源逐项确认，本轮不自动增点。
4. 微信抓取正文仍保留少量远程推广图引用；它们不影响主体阅读，也不会进入发布资产。若要离线归档到完全无远程引用，应作为单独清理任务处理。
